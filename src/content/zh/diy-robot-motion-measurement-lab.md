# Hands-On Lab：300元自建机器人运动评测台

> **一句话结论**：量化自己机器人的真实水平，不需要激光计时和工业遥测。一台手机（摄像头 + IMU）、一个USB功率计、一把卷尺和一卷彩色标记带，总预算300元以内，就能测出速度、跌倒率和真实续航三组可复现数据——关键是固定赛道、固定口径、把失败也记进表格。

## 1. 为什么个人也需要一套评测台

昨天我们把世界人形机器人运动会拆成了一套工程评测框架：速度、稳定性、能耗、操作成功率和人工接管次数。但那张表对多数极客有一个现实障碍——**没有官方赛场的测量条件，参数就停在了"感觉很快""感觉挺稳"。**

这正是自建评测台的价值：用最便宜的消费级工具，把"感觉"换成"数字"。官方赛场能测400米，个人可以先测5米直线、10次往返；官方有激光计时门，个人可以用摄像头的帧率计数替代；官方有遥测系统，个人可以用手机IMU和功率计逼近。

**评测台不解决"造一台更强的机器人"，它解决的是"知道自己这台到底行不行"。**后者往往是DIY项目最容易跳过、却最影响下一步决策的一环。

## 3. 测速度：摄像头帧率计时法

### 原理

手机摄像头每秒固定拍摄30或60帧。只要知道机器人通过起终点之间的**帧数**，就能算出用时：

```text
速度(m/s) = 赛道长度(m) / (帧数 / 帧率)
```

例：5米直线赛道，30fps拍摄，机器人通过用了45帧，则用时1.5秒，速度约3.33 m/s。

### Step 1：固定赛道与机位

- 用卷尺量出5米直线，起终点贴彩色标记带；
- 手机横向固定在赛道侧方，正对起终点连线的中点，确保起终点都在画面内；
- 机位离地高度、距离、角度都记下来，下次测试保持一致。

### Step 2：标记与计时

- 机器人正前方/正上方贴一个高对比色块，作为视频里的跟踪点；
- 用慢动作或高帧率（60fps优先）拍摄；
- 回放时逐帧找色块压过起点线、终点线的帧号，两者相减即为帧数。

### Step 3：多跑取平均

单次成绩没有意义，至少跑5次，记录最快值与平均值。**只报最快值，等于自动隐藏了热衰减和偶然性。**

## 4. 测跌倒与姿态：手机IMU + 视频人工标注

### 方法A：手机IMU（贴/绑在机器人上）

用免费的传感器记录App（如 Sensor Logger、Physics Toolbox），把手机固定在机器人背部，采集加速度与角速度：

- **加速度突刺**：行走中Z轴（竖直）加速度出现远大于常态的尖峰，通常是落地冲击或碰撞；
- **角速度突增**：横滚/俯仰角速度短时间内大幅跳变，常对应失稳或摔倒；
- **姿态角漂移**：静止时姿态角长时间回不到基线，说明站立自平衡在退坡。

给这些信号设一个阈值，超过阈值就标记一次"事件"，再对照视频确认是真跌倒还是误报。

### 方法B：视频人工标注（更简单）

不装IMU也能做：逐段回放视频，人工记录：

```text
跌倒次数 / 人工扶起次数 / 自动恢复次数 / 摔倒到恢复的耗时
```

跌倒率 = 跌倒次数 ÷ 总任务次数。**关键是把"自动站起"和"人扶起来"分开记**——后者在真实部署里意味着必须有工程师在场，是两种完全不同的产品成熟度。

## 5. 测续航与能耗：USB功率计

机器人"能跑多久"和"跑一次花多少电"是两回事。前者看电池，后者看能耗，都值得测：

### 测整机能耗

把USB功率计串在充电器与机器人之间，充满后读取累计电量（Wh）：

```text
单位任务能耗(Wh) = 本次充电累计电量(Wh) / 期间完成的任务次数
```

例：一次充满记录到120Wh，期间跑了10次5米往返，则每次任务约12Wh。

### 测任务前后电量

更简单的方式是直接记录任务前后电量百分比，配合电池标称容量估算能耗：

```text
能耗(Wh) ≈ 电池标称容量(Wh) × (起始电量% - 结束电量%)
```

### 为什么要测

速度、稳定性和能耗必须放同一张表。只看速度，会漏掉电池热管理和续航衰减；只看稳定性，会漏掉单位任务的真实成本。**三个数字一起看，才能判断这台机器是"能跑"，还是"能持续地跑"。**

## 6. 一张最小可行的CSV记录表

每次测试只记一列，长期积累就是一台机器人的完整画像：

```text
run_id, robot_id, firmware, date, ambient_c, track_length_m,
battery_start_pct, battery_end_pct, energy_wh,
lap_ms, avg_speed_ms, fall_count, human_takeover,
imu_event_count, mission_result, note
```

三条纪律：

1. **失败也记**。一次跌倒暴露的步态、摩擦或热保护问题，比十次成功更有价值；
2. **固定口径**。赛道长度、机位、电量起始、帧率，任何一项变了都要写进 note；
3. **存原始素材**。视频和IMU日志保留下来，事后能回放复核，而不是只存一个数字。

## 7. 局限与进阶

这套方案有明显的精度边界，使用时心里要有数：

- **摄像头滚动快门**：高速运动时画面可能扭曲，高速下优先60fps或更高，机位正对中点；
- **IMU漂移**：手机MEMS传感器长期漂移，适合测短时事件（跌倒、冲击），不适合长时间姿态积分；
- **人工标注误差**：帧级判读有±1帧的不确定性，起终点用高对比色块可降低误判。

预算允许时，可以逐步升级：

| 升级项 | 带来的提升 |
|---|---|
| 激光/红外计时门 | 毫米级触发精度，替代帧率判读 |
| 智能手机换成专用IMU（如MPU6050/BNO055） | 更高采样率与更小的漂移 |
| ROS 2 + rosbag | 结构化记录所有话题，事后完整回放 |
| 压力板/六维力传感器 | 测足底接触与落地冲击力 |

## 8. 结论：先有尺子，再谈进步

官方赛场与个人工作台之间，差的不是机器人，而是一把稳定的尺子。300元的评测台做不了奥运级计时，但足以回答三个对DIY项目最有用的问题：

- 改了步态参数之后，速度是变快还是变慢、能耗是升还是降？
- 连续跑10次，跌倒几次、需要人工扶起几次？
- 满电到低电，性能到底衰减多少？

这三个答案，比任何"感觉更好了"都更能指导下一步该改什么。**先建尺子，再谈进步，是所有从"能跑"走向"可交付"的机器人项目的共同起点。**
